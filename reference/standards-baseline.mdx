The machine-readable [snapshot](/standards/snapshot.json) records each source path and SHA-256. `npm run lint:standards` validates the required inventory and metadata shape.

## Status interpretation

- **Active** means the upstream Preamble currently labels the SEP active at the pinned commit. It does not mean a target implements it or RampSpec tests it.
- **Final Comment Period** is an upstream review status. Rule packs must retain the pinned text and prepare for incompatible changes.
- **Draft** behavior can change without a stable compatibility promise. Draft rules must be clearly labeled and cannot block a default production gate unless an organization opts in.
- **Planned coverage** means no tagged backend rule pack provides executable evidence yet.

## Refresh procedure

1. Clone the official repository and record the new full commit SHA.
2. Read the Preamble for all ten supported documents; do not infer status from an issue or secondary article.
3. Compute SHA-256 over each file's exact bytes.
4. Diff normative language and categorize added, removed, and changed requirements.
5. Coordinate rule and scenario updates in `rampspec-backend`.
6. Add compatibility and migration notes for semantic changes.
7. Update `standards/snapshot.json`, this table, and every protocol guide link in one reviewed change.
8. Run `npm run lint:standards` and the complete docs build.
9. Publish coverage as implemented only after the backend tag and release manifest identify the matching snapshot.

The [classification policy](/reference/terminology#rule-classification) explains why an upstream requirement, interoperability recommendation, and RampSpec policy must remain distinct.
