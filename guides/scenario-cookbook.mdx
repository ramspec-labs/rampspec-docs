This cookbook turns the [scenario language](/reference/scenario-language) into small, reviewable patterns. Each stored document has one purpose, explicit requirements, catalog references instead of destinations, bounded behavior, and cleanup where it can create state.

<Warning>
  Every file is **Planned**. The backend has not released the scenario schema,
  compiler, action catalog, fixture catalog, or lock format, so these files are
  not executable and have no golden lock digest. Their `.planned.yaml` suffix
  prevents automation from treating them as released scenarios.
</Warning>

## Using the cookbook

Choose the smallest pattern that exercises the intended contract. Replace only declared parameters with organization-approved references. Do not paste target URLs, secrets, customer data, signing seeds, or arbitrary actions into a document.

Before a planned example can lose its suffix, maintainers must import a tagged backend schema bundle, resolve every `uses` identifier from the matching action and fixture catalogs, validate the file, compile it twice to the same suite-lock digest, run it in a controlled target, verify its report and cleanup, and publish compatibility in the release manifest.

Each example is referenced from this page so documentation CI rejects a missing file.

## Review checklist

A cookbook contribution must prove:

- one stable scenario purpose and metadata ID;
- only released schema fields, action IDs, fixture IDs, and typed references;
- explicit network and capabilities, with no raw destination;
- bounded amount, fee, duration, retries, matrix size, and retention;
- secret handles instead of values and no sensitive output flow;
- dependency edges for every consumed output;
- target and provider side effects covered by `always` cleanup;
- deterministic pass, fail, skipped, indeterminate, cancellation, and cleanup behavior;
- a compatible release manifest and reproducible suite-lock digest.

## Validation status

Prettier parses and normalizes every stored YAML file during this repository's quality build. The snippet reference check proves the files exist, content checks prove this page is navigable, spelling and external-link checks cover the complete set, and the static export renders the cookbook.

Those checks do not replace JSON Schema validation or compilation. The executable exit check remains blocked by the missing backend schema and catalogs. Until those artifacts arrive, the examples demonstrate the complete intended patterns while remaining unavailable to the CLI, API, UI, runners, schedules, and release gates.
