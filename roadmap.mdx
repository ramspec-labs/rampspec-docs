The RampSpec roadmap separates planned work from implementation evidence and deployed behavior.

## Current status

| Area                                          | Status                       | Evidence                         |
| --------------------------------------------- | ---------------------------- | -------------------------------- |
| Four repository boundaries                    | Implemented in documentation | Repository ownership page        |
| Mintlify toolchain and quality checks         | Locally checked              | `npm run build`                  |
| Runtime API, schemas, contracts, and frontend | Planned                      | No tagged runtime releases yet   |
| Testnet and pubnet integrations               | Not deployed                 | No deployment manifest exists    |
| External review and adoption                  | Not claimed                  | No review or pilot record exists |

## Delivery order

The next documentation units establish product boundaries, architecture, generated-reference contracts, standards, safe test modes, and the first protocol guides. Runtime claims will be promoted only when the owning repository supplies a compatible tag and verification record.

## Change control

Release-specific documentation remains bound to its compatibility manifest. A roadmap item is not a release promise, security review, certification, or adoption claim.
